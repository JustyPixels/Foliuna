# Foliuna architecture

## Product flow

Search booru → inspect post → explicitly download → preserve media, source snapshots and categorized tags → browse offline in Gallery (phase 3) → organize local collections (phase 4, implemented).

Foliuna is booru-first. Remote pages are never embedded. Built-in e621, Danbooru, Gelbooru, Rule34.xxx, Safebooru, AIBooru, Yande.re and Konachan plus custom Danbooru/Gelbooru JSON APIs are available. Safe-only mode uses the provider’s General/Safe query and filters normalized ratings; all-ratings mode is an explicit selection. Browsing images is separate from archiving. Online original still images are fetched for viewing after Full size is selected; offline details fit the already-saved original. Visible GIFs use original animations, video is fetched on play, and SWF is fetched after the explicit Ruffle control. Only Download original creates archive records.

## Code boundaries

| Layer | Responsibility | Access |
| --- | --- | --- |
| `src/renderer` | React search, shared grid/details/playback, Collections, Settings, account and tag controls | Typed per-capability bridge; registered local media |
| `src/preload` | Sandbox-compatible bridge | Explicit invoke methods, no generic IPC or event objects |
| `src/shared` | DTOs, provider/category lists and runtime input validation | Pure values/URL parsing |
| `src/main/ipc.ts` | Sender authorization, capability routing and sanitized results | Known services; no arbitrary SQL, paths or URLs from UI |
| `src/main/credentials.ts` | Encrypted account persistence, status and removal | OS secret storage, profile credential files |
| `src/main/adapters` | Provider API requests, pacing and response normalization | Fixed engine-specific HTTPS post/tag endpoints; e621 current-account endpoint |
| `src/main/media.ts` | Bounded, validated preview/sample/original media delivery | Known post URLs on approved HTTPS CDN hosts, no credentials |
| `src/main/archive` | Original transfers, local gallery, hashes, sidecar import/checks, journal recovery | Selected library folder; allowlisted credential-free CDN requests |
| `src/main/database.ts` | Transactional migrations through schema v3 | SQLite, foreign keys, WAL and synchronous FULL |
| `src/main/index.ts` | Lifecycle, native folder picker, Windows encryption, local protocol and session restrictions | Application profile and explicit services |

`BooruAdapter` exposes search, details and fresh `getSnapshot`. The e621 adapter retains its original snapshot format; compatible adapters produce canonical e621-shaped fields plus `provider_metadata` (the complete fetched object), `foliuna_source` (validated connection definition) and `source_rating`. This reuses existing archive/gallery queries without discarding provider-only fields. React receives normalized records only. All configured adapters register in main; e926 remains archive-only. Custom IDs derive from engine/site/API URLs, so changing a host cannot silently reuse credentials or rebind earlier provenance. See BOORUS.md for endpoint/auth/rating compatibility.

New searches are user initiated. Both numbered pagination and optional infinite scrolling use 24 posts and stop at page 750. Infinite loading has a synchronous in-flight guard, appends only new identities, stops automatic loading after errors/no-new-post pages, and exposes a manual retry. Submitted query/filter values are retained. Shared PostGrid uses stable per-column assignment for natural proportions, avoiding column rebalancing on append; crop mode aligns cards. PostDetails remains mounted during previous/next navigation, and reaching the loaded end can append a page. Loaded metadata/cards remain resident (up to the provider page cap); virtualizing very large sessions is future performance work. A full page suggests another may exist; no total count is claimed. Content-filter changes clear results, and pagination uses the submitted query/filter rather than later draft edits. Safe-only defaults on, canonicalizes rating terms to the provider’s Safe/General query and filters unexpected non-safe results in main. Sequence IDs and effect cleanup ignore stale responses. Remote description, tag and source strings render as plain text. Missing/deleted/unsafe media URLs retain metadata without loading content.

## Electron trust boundary

The privileged app page is `foliuna://app/index.html`. A separate viewer.html window has no preload. Flash uses swf.html on the separate foliuna://player origin and cannot read its parent DOM or bridge. Its custom protocol resolves files under the renderer bundle, rejects decoded traversal, backslashes, NULs, unexpected hosts and extensions, and supplies MIME types, CSP and nosniff headers. No development server has access to the bridge.

BrowserWindow explicitly enables sandboxing, context isolation and web security; Node integration, webviews and insecure content are disabled. Session permission requests/checks deny access except fullscreen from the owned viewer window main frame. Navigation, redirects, webview attachment, arbitrary popups and Chromium-initiated downloads are blocked. The only child navigation allowed is the exact local SWF page plus validated provider/ID fragment. The request filter permits local bundle resources and registered image/media/XHR routes. Main CSP permits self images/media and only the local player frame, and blocks renderer connections, objects and remote scripts. The player permits self connections and wasm-unsafe-eval for bundled Ruffle, but remote connections remain blocked by both CSP and the session request filter. Ruffle also disables page-script access, networking/navigation, downloads and background execution; script execution duration is bounded. No plugin/object support is enabled. Decoding/emulation stays in sandboxed renderers.

### Media rendering boundary

Search/detail capabilities register approved media URLs in a bounded 20,000-post map (covering the 750×24 discovery cap) and return same-origin media routes keyed by provider, numeric post ID and preview/sample/original variant. A route can only resolve metadata already returned by an adapter. No general URL proxy, filesystem route, auth header or new generic IPC capability is exposed. Demo images remain known local SVG assets.

The loader accepts GET/HEAD and single byte ranges, exact local origin/path, an approved HTTPS CDN media URL, redirect rejection, a 60-second timeout, MIME/magic-byte checks and a streamed size cap (8 MiB preview/sample, 100 MiB original). It limits active transfers to two and the waiting queue to 48. In-flight URL requests coalesce and verified bytes are cached for five minutes with a 128 MiB cap. Range and HEAD responses use those bytes, never a separate upstream range proxy. CDN 429/503 responses impose at least 30 seconds of cooldown and honor longer Retry-After. Fetching begins only for near-visible thumbnails or requested detail/playback media. In-progress shared transfers finish under the timeout after callers leave; queued aborted requests are skipped before fetch. Valid media returns its verified MIME plus nosniff; failures return error statuses, not remote HTML. No credentials are attached. This fixes the reproduced ERR_BLOCKED_BY_ORB for direct CDN images while retaining browser security.

Natural-grid thumbnails preserve proportions; crop mode uses cover. Details default to sample/preview fallback for still images, with explicit original selection. GIFs use original animations. Videos use controls and preload=none; verified originals are buffered before first playback and seeking reuses cached byte ranges. This deliberate bounded buffering can delay large video playback. Flash is an explicit, separate-origin iframe running the locally bundled @ruffle-rs/ruffle 0.7.1 runtime with JS/WASM assets and licenses. Unsupported Flash features/codecs and blocked external assets remain compatibility limits.

Twenty-nine named bridge functions (including custom connections and five collection operations) cover search/details/archive/credentials, preference get/save, tag suggestions, sanitized current-account access and opening a media window, plus six local gallery/search/maintenance/thumbnail capabilities. Each app handler verifies the owning WebContents ID, exact local index URL and main-frame identity. The viewer has no preload/bridge, and player frames cannot invoke those handlers. Viewer content is generated from validated post metadata and fixed local routes. Its fullscreen permission is scoped to that owned window and main frame; F11 also toggles native fullscreen and Escape exits it. Closing the child focuses the existing parent details.

PreferenceStore validates grid/browsing enums and at most 500 distinct, bounded single-token local favorite tags, serializes atomic profile writes and preserves unreadable files. Discover and Gallery share these preferences; Collections uses them too. e621/Danbooru API suggestions and Rule34’s documented API-domain autocomplete use the shared queue/cache; other Gelbooru/Moebooru suggestions come from observed loaded tags (labelled Recent tag). No categories are guessed from flat lists. Tag autocomplete waits 650 ms, serializes its active suggestion call, ignores stale results, and requests at most eight validated prefix matches. No bulk tag dump or periodic background polling is performed. Clicking a detail tag opens keyboard-accessible Add/Exclude/Favorite actions; adding/excluding edits the draft only.

Account access requires a saved e621 entry and calls /users/me.json through the shared queue. Only ID/name/level/joined/upload and favorite counts plus bounded site favorite_tags reach React; email, blacklist, key-related and unknown fields are excluded. Artist tags are browsable in both the site and local favorite-tag lists. Site favorite-post search uses fav:!<account-id> and the existing safe filter. There are no remote account writes or invented artist-subscription endpoints.

External post links are derived from provider + numeric ID plus a validated configured or archived connection definition. Archived links continue to work after a custom connection is removed; arbitrary renderer URLs are never accepted. Arbitrary source URLs remain text. The native folder picker chooses archive roots; a renderer cannot supply a root. Unexpected errors become sanitized result objects without raw exception details. Tests use temporary profiles and never real account secrets.

## Credentials and authentication

Settings selects a built-in/custom connection and has one transient password input. It is not stored in React state, browser storage or form history; submission and connection changes clear it. The saved key is never returned. Settings exposes connection definitions and only saved/locked credential state and username/numeric ID. Existing e926 files are preserved without display/reuse. Unreadable encrypted entries block requests rather than silently becoming anonymous. Custom boorus persist separately in profile boorus.json; unknown fields and credentials are not accepted into definitions. Stable IDs and strict validation keep credential filenames bounded.

CredentialStore serializes reads/mutations, encrypts username + key together, and uses flushed temporary files plus rename to replace per-provider encrypted entries. Failed encryption/replacement preserves the previous entry. Removal deletes the local entry without claiming to revoke the provider's key. No decrypted-key cache is kept. Requests briefly hold a decrypted JS string in main; JS memory cannot promise secure erasure.

The supported persistent backend is Electron asynchronous safeStorage on Windows (DPAPI). Save is refused when the secure backend is unavailable; non-Windows persistence is disabled pending a reviewed implementation. DPAPI protects other Windows accounts, not other programs running as the same user. This does not promise that only the human and site can ever access a key. See Electron's safeStorage documentation.

API calls use HTTPS Basic Authorization for e621/Danbooru or documented user_id/api_key query authentication for Gelbooru/Rule34. Keys are appended only immediately before the exact configured API request, never to caller URLs or cache keys. Media requests carry no API credentials/cookies. Sites using auth:none never read a saved entry. Rule34 requires credentials before any request; malformed numeric IDs fail locally. Credential mutations invalidate caches. Settings reports a valid JSON connection response without claiming to prove every site permission. No real key was supplied during development, so authenticated live access remains unverified.

## Provider and media transports

ApiClient maintains one bounded serial queue shared by all providers, spacing actual starts by at least 1,100 ms. It validates a fixed read endpoint/query allowlist beneath the exact configured API base and resolves that connection’s credentials at dispatch. Requests have a 15-second abort signal including DNS/body, an 8 MiB JSON cap, redirect rejection, descriptive User-Agent, omitted cookies and no automatic retries. HTTP 429/503 impose at least 30 seconds of cooldown or longer Retry-After. Bounded/coalesced caches (120 entries/32 MiB) use provider ID plus credential-free URL: one minute for search/details/account, 24 hours for prefixes. Generation invalidation stops obsolete requests repopulating the new cache. Archive snapshots bypass the cache. Safebooru’s observed zero-byte JSON response means no matches; UTF-8 BOMs are handled and other empty/HTML/invalid responses fail explicitly.

Viewed images may enter Chromium's profile cache but never create archive records. Archive transfers run in main only after an explicit Download original command. One archive transfer can run at a time. It re-fetches current source metadata through the paced API adapter, then requests an exact allowlisted HTTPS CDN original without credentials or redirects. Signed/query-bearing download URLs are refused. Archive transfer time is capped at 120 seconds and size at 100 MiB; the declared size when supplied, received byte count, MIME, magic bytes and provider MD5 when available are checked. Missing sizes are streamed under the cap and the verified byte count is recorded before journal publication. SHA-256 is the deduplication key. Supported archive formats: JPEG, PNG, GIF, WebP, WebM, MP4 and SWF. Flash signatures also bound their declared expansion size to 100 MiB; originals are never executed by the archive service. No executable/SVG original or automatic media opening is supported.

Cancellation aborts a transfer and cleans up its partial file. Finalization already in progress is allowed to complete. Shutdown cancels/waits for transfer cleanup, waits for encrypted writes, closes SQLite and releases the library lock before exiting.

## Library selection and SQLite

The app profile stores browsing preferences/local favorite tags in preferences.json, the selected root in library.json and encrypted credentials separately. A library stores its database in `.foliuna/library.sqlite`, in-progress data under `.foliuna/staging`, and originals/sidecars under `media/`. A phase-1 profile database is preserved without implicit import or movement.

Roots are canonicalized from native-picker results. Managed subfolders must be real directories; symlinks or unexpected file types at managed boundaries are refused. Fixed hash/UUID filenames constrain recovery paths. The SQLite database and existing WAL/SHM/journal files are checked before opening. An exclusive PID/token library lock prevents multiple profiles writing the same library; a stopped process's stale lock may be reclaimed. These checks do not claim protection against malicious simultaneous filesystem edits by another program running as the user.

A preflight checks safe publication. publishNoReplace first attempts a hard link, then uses fs.copyFile with COPYFILE_EXCL only for unsupported-link/filesystem errors. It never replaces an existing destination. Copies are flushed and the caller verifies hash/size before committing metadata. A crash can leave a partial copied destination; recovery preserves that conflict and the verified prepared staging file instead of overwriting it. After closing the app, move the conflicting destination aside and retry the same folder. Tests force no-hard-link/concurrent publication; actual exFAT devices and physical power-loss behavior remain unverified. Sidecars and media themselves remain portable files.

SQLite uses node:sqlite in main to avoid native add-on rebuilding on Windows. Short migrations/transactions are synchronous; streaming/hashing uses async I/O. Foreign keys, busy timeout, WAL and synchronous FULL are enabled. Unknown newer schema versions fail without reset. Migrations are transactional; version 1 data is preserved when adding version 2 tables.

| Table | Relationship |
| --- | --- |
| assets | One physical media file per unique lowercase SHA-256, relative path and verified byte count |
| source_posts | One provider/post identity points to an asset, canonical URL and latest metadata |
| tags / post_tags | Latest source snapshot's categorized tags, indexed for gallery lookup |
| source_snapshots (v2) | Immutable capture IDs, raw source metadata, categorized tags and capture timestamps |
| download_journal (v2) | Downloading/prepared operations retained until media, DB and sidecar agree |
| collections / collection_assets | Implemented local memberships; recoverable portable snapshot projection |

An asset with source references cannot be removed through accidental cascading deletion. Repeated captures of the same source/bytes retain older snapshots. If that source's bytes change, SOURCE_CHANGED preserves the earlier archive rather than silently replacing it. A future explicit revision model is needed before replacing archived media.

## Save/recovery sequence

1. Lock the active operation, recover pending work, and re-fetch a source snapshot. Insert a downloading journal row with a generated staging UUID.
2. Stream to a new exclusive `.part` file, enforce limits and verify its signature/checksum, calculate SHA-256, and flush the file. Interrupted/incomplete streams are never published.
3. Persist a prepared journal plan containing the validated hash, byte count, provider/post, source metadata and capture ID. Credential fields and URL credentials/transient CDN parameters are removed before persistence.
4. Reuse an existing hash asset or publish the staged original without replacement using a hard link or an exclusive copy on filesystems lacking hard links. Existing files are hash-verified; conflicts are preserved and recovery stops.
5. In a short SQLite transaction, create/reuse the asset, update latest source metadata/tags and insert the capture snapshot once by its unique capture ID. No source identity is rebound to different bytes.
6. Regenerate the adjacent schema-v1 sidecar from all committed sources and snapshot histories. Flush a temporary file and rename it into place. Only then remove staging/journal records and report success.

On recovery, downloading rows discard only their generated incomplete staging files. Prepared rows validate their plan and paths, verify existing/staged media, and rerun finalization idempotently. Capture IDs prevent duplicate snapshots after a crash between SQLite commit and sidecar publication. If a media/sidecar write, permissions check or integrity check fails, the prepared plan and data remain available for retry. Settings can reopen the same folder after the underlying issue is resolved. This handles application interruption and injected I/O failures; it is not a hardware-failure or backup guarantee.

See SIDECAR.md for the shipped portable format, GALLERY.md for restore/query behavior, and COLLECTIONS.md for portable local memberships. Gallery, sidecar import, missing-index reconstruction and Collections are implemented.

## Offline gallery and maintenance

Gallery owns no fetcher and has no adapter dependency. GallerySearch compiles bounded exact terms to parameterized EXISTS/JSON predicates on source_posts/post_tags. Every term matches the same source, then a window function selects one representative matching source per asset. Grid rows group by asset SHA-256 while detail requests pin the selected provider/post identity. Existing e926 provenance is local data. Query/DTO metadata remains plain text; private credentials are never read for gallery operations.

Local GET/HEAD/single-range routes use /gallery/<64 lowercase hex>/<thumbnail|original> on the app/player origins. Routes resolve only indexed assets in the currently selected library, reject arbitrary paths/URLs, inspect each path component for links, bound reads and check originals against stored size, signature and SHA-256. A 128 MiB/256-entry memory cache is invalidated by file identity/size/mtime/ctime; all original responses are verified bytes. Two transfers and a 48-item queue bound concurrent reads. Cache-Control:no-store prevents Chromium serving an original after the library is switched or file removed. Missing/unsafe originals never fall back to provider URLs.

Thumbnail creation uses canvas in the sandboxed UI after decoding a local image or first video frame; no native image decoder is added to main. The write-only cacheThumbnail capability accepts only known asset hashes and at most 2 MiB of PNG bytes with IHDR dimensions at most 512×512, and writes only .foliuna/thumbnails/<hash>.png through a checked directory and atomic replacement. Derived thumbnails are disposable; originals are never changed. GIFs animate locally when visible. Videos may buffer local originals before first playback/thumbnail creation. Flash uses the same separate-origin Ruffle player with a gallery/hash identity and no networking.

ArchiveLibrary.access pins the selected root/database for local reads and close waits for pending reads. Selection refuses an active read/write; maintenance waits for existing reads and blocks new reads/downloads/selections while operating. Read-only gallery access can continue while a normal immutable original download runs. A shared cancellation signal stops maintenance at file boundaries; a publication/transaction already running finishes safely.

Sidecar import inventories existing files before writing, skips links/dot folders, limits traversal to eight levels/100,000 entries and reads individual sidecars at most 16 MiB. It validates schema v1, basename/Windows device-name constraints, provider/positive IDs/canonical URLs, capture dates, tag bounds/categories, metadata identity/format/size and actual original signature/size/SHA-256. Unknown schemas and conflicts stay untouched. Input media is copied only to generated canonical paths without replacement; existing valid canonical sidecar history is merged before rewriting it. Source identity cannot bind to different bytes. Each sidecar’s rows commit transactionally, stable capture fingerprints prevent duplicate histories, and older/equal-time imports do not replace existing latest metadata. Interrupted imports preserve input files and completed commits; rerunning is idempotent. There is no destructive DB reset. Sidecars missing a capture ID get stable import IDs without changing schema v1.

Reconciliation verifies indexed originals and sidecars, preserves damaged/conflicting files, recreates absent sidecars from committed history, and scans the selected root for a matching moved original by hash. It creates a canonical verified copy and leaves the moved candidate intact. Genuinely missing originals retain all rows and remain searchable; up to 50 relative-path issues reach the UI. Changed provider revisions are explicitly refused; the user can choose another archive folder to preserve both. The app does not replace revisions, delete media or repair unknown databases automatically.

## Multiple-provider security and portable identity

Provider definitions allow public HTTPS site/API base URLs and explicit media origins only. The API path, query names and numeric IDs are built by adapters in main; React cannot submit arbitrary fetch URLs. Custom configuration is capped at 32 connections and 24 extra media origins each. The default network transport resolves DNS, rejects private/special addresses, pins the checked address in the TLS lookup while retaining hostname certificate verification, rejects redirects, omits cookies and requests identity encoding. DNS cancellation is included in request timeouts. Tests can inject a fetcher only through services or the explicit unpackaged test-network entry path; packaged execution always uses the checked transport.

SQLite v3 rebuilds only source_posts to remove the e621/e926 CHECK constraint, retaining primary keys, source/tag/snapshot and collection relationships. Foreign keys are checked before commit and re-enabled afterward; failures roll back. Newer schemas are refused, old captures and credential files are not rewritten, and sidecars keep their v1 envelope. Custom archived definitions must reproduce their stable identity and canonical source URL during import. Gallery does not consult a provider store or make network requests. Source metadata remains immutable per capture.

BOORUS.md documents the built-ins, custom setup, credential scope, flat-category and account limitations, official API references and metadata-only live checks. Default automated tests never use real provider credentials or network traffic.

## Collections

Collections reuses Gallery search and media capabilities; GalleryRequest accepts an optional validated collectionId. The main query loads/validates the portable snapshot, restores its searchable SQLite projection if necessary, then adds a parameterized membership predicate before SHA-256 grouping and pagination. No provider, credential or network dependency is added. Five named IPC capabilities list/create/rename/delete collections and set membership; only known indexed hashes may be added. Deletion clears collection membership only, never assets, captures, media or individual sidecars.

The authoritative version-1 .foliuna/collections.json stores monotonic library-local IDs, Unicode-normalized names and SHA-256 membership arrays, including unindexed hashes. Bounded/path/link validation precedes reads and writes. Mutations use ArchiveLibrary.maintain to wait for pinned reads and exclude downloads/folder changes. The flushed atomic snapshot is published before a transaction updates existing collection tables; failed projections are restored from the saved file on next access. A per-DB content hash/asset-count cache avoids repeated projection rebuilding. Pending memberships reattach as verified sidecar imports grow the index. Malformed/newer snapshots block Collections, preserving the file and leaving ordinary Gallery available. No schema migration is needed; DB stays v3 and per-media sidecars stay v1.

CollectionDialog manages memberships from shared archived PostDetails; CollectionsPanel handles named collections, counts, rename and confirmed deletion. Discover cannot collect unsaved remote posts. Search/filter changes and detail navigation remain scoped to the selected collection. See COLLECTIONS.md for the portability format, limits and recovery workflow.

## Release payload and rendering cost

Electron Builder 26.15.3 packages a minimal public manifest plus compiled main/preload/renderer, local player, icon and licenses. Seven actual fuse states and embedded ASAR header/file/block hashes are checked after packaging; normal development Electron is never modified. The packaged demo is an explicit --demo switch with a separate profile. A native launch argument can choose another user-data directory; this adds no renderer capability.

Search appends use one Set for asset/source identities and suppress duplicates both across pages and within a response. Shared memoized grid/cards skip unchanged renders while typing; natural-layout columns are built in one pass. Image intersection observers disconnect after first visibility, retaining the same image element across scroll exits. Images still load lazily, and requests retain all queue/cache bounds. Loaded cards remain mounted; very large infinite sessions still need virtualization if memory becomes a measured problem.

## Android preview and shared platform boundary

The Android 0.1.0-preview.1 app uses Capacitor 8.5.3 with the same React components, green artwork, provider definitions and typed FoliunaApi as Windows. Android builds only the main UI; Electron/player/floating-window pages are absent. platform() describes supported controls; exportLibrary() is an explicit Android destination-picker operation. Windows responds with its own capabilities and a structured unsupported-export response; its archive/import behavior is unchanged. Native Android methods are named and validate inputs independently of the facade.

Kotlin Core/Services/Booru/Archive/Media own Keystore AES-256-GCM credentials, fixed provider API endpoints, checked DNS pinned to OkHttp sockets, redirect/private-address rejection, credential separation, shared serial 1.1-second API pacing, cooldowns, bounded caches/coalescing and checked streaming media. Responses are normalized through native BooruAdapter implementations with compatibility fixtures generated from the Windows normalizers. API keys never return to React or reach media hosts. The web facade has no generic fetch, SQL, path or credential-reading capability.

Only bundled UI loads at https://localhost. Remote navigation, frames, generic Capacitor file/content routes and general HTTP/cookie/WebView-path plugins are disabled. The main response receives CSP permitting self scripts and exact hashes of the trusted injected Capacitor bridge. Native WebView file/content access, mixed content, cookies, popups and permissions are denied. Same-origin media routes resolve only registered provider/post/variant identities or indexed SHA-256 assets. Media ranges support playback after native MIME/signature/size validation. Flash is deferred on Android.

AndroidX bundled SQLite provides consistent window-function/JSON behavior across API 26/36. Originals, source history, v1 sidecars, collection snapshots and recovery journals remain in app-private canonical roots. Publication first attempts a hard link and uses exclusive copy when Android SELinux rejects it; the prepared journal preserves the verified staging original. Unknown schemas/corrupt files/conflicts are preserved, never reset. Collection mutations publish the authoritative v1 snapshot before updating SQLite. Downloads cancel on leaving the foreground; no background service or bulk downloader is installed.

Export holds the archive operation/database lock for one consistent snapshot and writes a newly created SAF folder: media originals, adjacent v1 sidecars and .foliuna/collections.json. Credentials, settings, caches and the database are excluded. An incomplete marker remains until every file completes. Verification reconstructs a fresh Windows Gallery/Collections with the actual importer, including categorized tags, multiple source captures, custom provenance and deduplication. No Android incoming-library import or synchronization is implemented.

Phone/tablet grids, bottom tabs, touch targets, safe-area spacing, keyboard handling, Android Back and a nested fullscreen viewer use the shared components. Testing uses native temporary services and fictional transports, never a renderer testing switch or real keys. API 26/36 instrumentation and an authorized Moto g14 API 34 test cover native/bridge/UI/media/archive behavior. Build/test outputs, SDKs and debug identities are ignored. See ANDROID.md and LOG.md for actual checks and remaining limitations.
