# Foliuna development instructions

Foliuna is a Windows-first booru searcher with a personal offline archive. Keep the booru-first flow: search → inspect → explicitly download → browse offline. The product name is Foliuna everywhere.

- Android preview shares React/contracts/definitions; Kotlin owns networking, Keystore, bundled SQLite, private files, recovery and SAF export. Keep only bundled UI in the privileged WebView. Disable Capacitor's generic HTTP, cookie and WebView-path plugins; block remote pages/frames and generic file/content routes. Maintain explicit typed methods and platform capabilities; do not expose raw credentials, SQL, paths or URL fetchers.
- Android is a separate debug-signed preview identity, minimum API 26/target 36. Use Android Studio's Java 21 runtime for local builds without changing global Java settings. No production signing keys/secrets. Keep foreground-only downloads and preserve unknown/damaged archives. Never test against a user's real profile or library.
- Set ANDROID_SERIAL to an owned emulator for Gradle connected tests: Gradle can uninstall the target app afterward. Authorized physical-phone checks must install with adb install -r and invoke instrumentation manually with temporary services; never clear or uninstall the user's preview.
- Android exports a newly created SAF folder containing verified originals, v1 sidecars and .foliuna/collections.json from one locked snapshot, excluding profile/settings/credentials. An interrupted export retains its incomplete marker. Run API 26/36 instrumentation, phone/tablet/rotation/Back/media checks and the actual Windows importer against the exported fixture before publishing an APK; document remaining real-device/live-key limits.
- Keep source, tests, lockfiles, licenses, useful docs, release history and this append-only LOG in GitHub. Remove only proven-obsolete/duplicate/generated files. SDKs, APKs, builds, signing keys, caches and private profiles stay ignored. Publish tested binaries through Releases, not Git. Do not replace or delete existing published releases.
- GitHub Pages source lives in site/; build reuses the existing icon/fictional illustrations/screenshots without duplicating presentation assets. Download links derive from real published release assets and refresh on release publication. Keep its fictional interactive demo free of booru requests, downloads and credential fields. Test /Foliuna/ project paths and mobile layouts. Commit coherent verified increments; maintainer/contact remains JustyPixels through GitHub Issues.

- Work in small coherent increments. Read affected callers, tests, fixtures, exports, and config before changing an interface. Prefer the platform and existing helpers; avoid speculative abstractions.
- React is unprivileged. No Node, filesystem, arbitrary URLs, SQL, raw IPC, stored credentials, or remote HTML in the renderer. The user-authorized password entry is transient and write-only: clear it immediately on submit and never return a saved key to the renderer. Keep sandbox, context isolation, web security, CSP, navigation restrictions, permission denial, and sender-frame validation enabled.
- Credentials use OS encryption in main and credentials scoped to the exact configured HTTPS API base. Use Basic headers for e621/Danbooru and documented numeric user ID/key query authentication for Gelbooru/Rule34; append secrets only at dispatch, never in cache identities. Never persist plaintext, send credentials to media CDNs, or include them in logs, SQLite metadata, sidecars or test traces. Refuse insecure encryption backends. Tests use fictional credentials only.
- Expose one typed preload function per capability. Validate every IPC input in main; return structured, sanitized errors. External post links must be derived from validated provider + numeric ID.
- New boorus implement `BooruAdapter`; transport, normalization, and provider-specific rules belong outside React. Mock at the transport boundary and exercise real normalization and IPC actions.
- Live discovery supports the built-in registry and user-configured Danbooru/Gelbooru JSON connections. Validate HTTPS/public hosts, fixed API paths, stable custom IDs and exact media origins; pin checked DNS to TLS and reject redirects/private destinations. Safe-only is default: canonicalize the provider’s General/Safe query and filter normalized ratings in main. Preserve legacy e926 archive identities/credential files without contacting e926 or silently reusing its key.
- Remote viewed media resolves only registered post metadata through same-origin validated media routes. Keep MIME/signature/size/timeout/concurrency bounds and never attach API credentials. Do not fix image loading by disabling web security, allowing arbitrary URL proxies, or weakening renderer CSP.
- Respect API terms: descriptive application User-Agent, shared serial queue, at least 1.1 seconds between starts, server cooldowns, timeouts, no automatic retries or restriction bypass. Never use real API traffic in default tests.
- Downloads must be explicitly initiated. Do not archive browsing previews. Before implementing downloads, read `docs/ARCHITECTURE.md` and `docs/ROADMAP.md`; preserve source metadata and categorized tags, SHA-256 deduplicate, and design crash recovery for media + SQLite + sidecars.
- No destructive schema recreation. Migrations run transactionally and refuse unknown newer schemas. Parameterize SQL values. Tests use temporary libraries; demo uses a separate profile.
- Non-trivial new logic needs a focused test. Run `npm run check` for changes spanning the app. Record actual commands, outcomes, and unverified limitations in append-only `LOG.md`; never rewrite old entries to imply a previous failure passed.
- Keep README, architecture, and roadmap aligned with implemented behavior. Phases 2/3/4 downloads, offline gallery, sidecar import, moved/missing-file checks and local Collections are implemented. Exclusive-copy publication supports filesystems without hard links; physical exFAT/power-loss validation and certificate signing remain pending. Phase 5 provides unsigned NSIS/ZIP candidates; read docs/RELEASE.md before packaging or publishing.
- Archive changes must keep no-overwrite publication, durable journal recovery, immutable capture history, cancellation and integrity checks. Only native-picked roots and generated relative paths reach file operations. Credential files stay in the app profile, separate from portable libraries.
- Browsing preferences/local favorite tags stay in the profile, separate from portable libraries. Reuse the shared grid/details/media components for Gallery and Collections. Site account access currently uses e621 only and is read-only and returns an explicit field allowlist; never return email, private account settings or raw user JSON.
- Cache only bounded read responses, invalidate on credential mutations and keep archive snapshots fresh. Load one infinite-scroll page at a time and stop automatic loading on errors. Flash runs only in the separate-origin bundled player with no preload and no remote networking; wasm-unsafe-eval must never be added to the main app CSP. Fullscreen permission is limited to the owned viewer main frame.
- Do not add dependencies for a few lines, parallel agents, authentication, telemetry, or publishing without a task that needs them.

- Gallery must remain independent of providers/credentials/fetch. Local routes accept only known asset hashes and fixed variants in the selected root; validate paths/links/size/signature/hash and never fall back to a CDN. Decode/generate thumbnails only in the sandboxed renderer, with a bounded write-only cache capability.
- Sidecar import/checks are explicit, cancellable library maintenance: verify input schema/media/provenance before indexing, preserve conflicts and histories, use transaction/idempotent capture fingerprints and no-overwrite publication. Never reset a damaged DB or remove missing/corrupt entries silently. Keep existing schema-v1 sidecars and v1/v2 databases readable through non-destructive v3 migration. Preserve raw compatible-provider metadata under provider_metadata with canonical fields and validated foliuna_source provenance; offline import must not require configured adapters.

- Collections are local SHA-256 memberships only. Never delete/rewrite media, source metadata or media sidecars when changing membership. Read docs/COLLECTIONS.md before changing portability: .foliuna/collections.json is the bounded authoritative snapshot and SQLite collection tables are a recoverable projection. Publish the file atomically before a transaction updates the projection; preserve unknown/unindexed hashes and invalid/newer files. Use the selected library lock/read pinning/maintenance exclusion and keep collection browsing offline.

- Release packages must use the clean work/package staging folder and verified ASAR/fuses. Run npm run package:win and npm run test:packaged after app changes. Keep test profiles separate, never weaken production fuses for automation, and never upload work directories, traces, profiles, libraries or signing secrets. Maintainer/contact is JustyPixels via GitHub Issues. Unsigned candidates are prereleases; do not claim certificate signing or authenticated live tests without evidence.
